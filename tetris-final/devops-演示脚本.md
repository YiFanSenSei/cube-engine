# DevOps 课堂演示 — 全流程脚本

**项目：** 俄罗斯方块 - 对战版（Electron + C++ Native Addon）
**总时长：** 约 5 分钟
**虚拟机 IP：** 192.168.254.3（已预装 GitLab Runner + SonarQube + Docker）

---

## 🎬 演示全流程

### 第一幕：提交代码触发 CI（0:00 - 0:30）

**操作：**
```
打开 GitLab 网页 → back_end/main.cpp → 编辑
找到 "Tetris API Server v1.0" → 改成 "v2.0"
提交到 main 分支
```

**讲稿：**
> "这是我们的俄罗斯方块项目。现在我修改一行后端代码的版本号，提交到 main 分支——CI/CD 流水线会自动触发。"

**要点：**
- 展示 GitLab 网页的提交操作
- 提交后切到 CI/CD → Pipelines 页面，展示新流水线正在运行

---

### 第二幕：流水线全绿展示（0:30 - 1:30）

**操作：**
```
等流水线跑完（或提前打开一条已完成的全绿流水线）
逐个点开每个 job 展示
```

**讲稿：**

**① build-backend**
> "第一阶段：编译 C++ 后端。CMake 自动配置并编译 API 服务器。这里用的是虚拟机上注册的 GitLab Runner，本地 shell 执行器，编译速度很快。"

**② test-unittest**
> "第二阶段：Google Test 单元测试。24 个测试用例覆盖了方块移动、旋转、碰撞检测、消行计分、AI 决策等核心功能。全部通过。"

**③ sonarqube**
> "第三阶段：SonarQube 代码质量分析。Cppcheck 自动扫描 C++ 代码，检测 Bug、代码异味、安全漏洞，结果上传到 SonarQube 平台。"

**④ eslint**
> "第四阶段：ESLint 前端代码风格检查。这里主要检测 JavaScript 代码规范，允许失败，不影响部署。"

**⑤ deploy**
> "最后是手动触发的部署阶段。生产环境中，确认前面所有检查通过后，点击 ▶️ 自动部署。"

---

### 第三幕：SonarQube 代码质量展示（1:30 - 2:30）

**操作：**
```
浏览器打开 http://192.168.254.3:9000
进入项目仪表盘
展示 Bugs、Code Smells、技术债务等指标
```

**讲稿：**
> "这是 SonarQube 代码质量平台，Docker 运行在虚拟机上。每次 CI 都会自动上传分析结果。
>
> 这里能看到：Bugs 数量、代码异味、重复代码率、技术债务百分比。每一项都可以点进去查看具体的代码位置和修复建议。
>
> 比如这里标记的 Code Smell，点进去就能看到是哪一行代码有问题。这帮助我们团队在代码合并前就发现并修复质量问题——也就是 DevOps 里常说的 '左移'（Shift-Left）。"

---

### 第四幕：自动部署 + 回滚演示（2:30 - 3:30）

**操作：**
```
在 GitLab 流水线页面 → 点击 deploy 阶段的 ▶️
等待绿色 → 在终端执行：
```

```bash
curl http://192.168.254.3:8080/api/health
```

**讲稿：**
> "点击部署后，Ansible playbook 自动执行：从 GitLab 拉取最新代码 → 编译 → 备份旧版本 → 启动新服务 → 健康检查。
>
> 这里最关键的是自动回滚——如果新版本的健康检查失败，系统会自动恢复上一版本，保证服务不中断。
>
> 验证一下：curl 请求返回 `{"status":"ok","activeGames":0}`——部署成功。"

---

### 第五幕：Docker 容器化展示（3:30 - 4:00）

**操作：**
```
打开项目的 Dockerfile 展示
```

**讲稿：**
> "我们还配置了 Docker 多阶段构建。第一阶段用 gcc:latest 编译 C++ 代码，第二阶段用 debian slim 生成仅 80MB 的运行镜像。支持 `docker run -p 8080:8080 tetris-server` 一键启动。"

---

### 第六幕：总结（4:00 - 5:00）

**讲稿：**
> "总结一下我们的 DevOps 工具链：
>
> **Git + GitLab** — 版本控制和代码托管
> **GitLab CI/CD** — 持续集成，5 阶段全自动流水线
> **GitLab Runner** — 虚拟机上注册，本地编译
> **Google Test** — 24 个单元测试覆盖核心逻辑
> **SonarQube + Cppcheck** — 代码质量自动分析
> **ESLint** — JS 代码风格检查
> **Ansible** — 自动化部署，含健康检查和回滚
> **Docker** — 容器化多阶段构建
>
> 从提交代码到编译、测试、质量分析、部署，全流程自动化，一键完成。"

## 📋 演示前检查清单

| 项目 | 检查 | 说明 |
|------|------|------|
| VM 已开机 | □ | 等待 1-2 分钟让服务自动启动 |
| GitLab Runner 在线 | □ | `sudo gitlab-runner status` |
| SonarQube 可访问 | □ | `http://192.168.254.3:9000` |
| 后端 API 已运行 | □ | `curl http://localhost:8080/api/health` |
| 有一条全绿流水线 | □ | 提前跑好一条，防止现场等 |
| GitLab 网页能打开 | □ | 提前登录好 |
| 浏览器已开好 SonarQube | □ | 提前登录好 |

---

## ⚠️ 常见翻车预防

| 问题 | 预防 |
|------|------|
| VM 刚开机 Runner 未上线 | 提前 2 分钟开机，先点一次流水线确认能跑 |
| SonarQube 启动慢 | 提前打开页面确认能访问 |
| 网络卡 CI 跑太久 | 提前跑好一条流水线，演示时直接点开绿色的展示 |
| deploy 点错分支 | 确认流水线是在 main 分支上跑的 |
| curl 返回 404 | 先确认后端进程是否在 VM 上运行 |
