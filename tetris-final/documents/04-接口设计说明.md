## 1. 概述

项目采用**三层接口架构**：

```
┌──────────────────────────────────────────────────────────────────┐
│  渲染进程 (Renderer) — Canvas / Web Audio                        │
│  ┌────────────────────────────────────────────────────┐         │
│  │  window.nativeAPI  (contextBridge)                  │         │
│  └────────────────────┬───────────────────────────────┘         │
│                       │ IPC (ipcRenderer.invoke)                 │
├───────────────────────┼──────────────────────────────────────────┤
│  主进程 (Main)        │ main.js                                 │
│  ┌────────────────────▼───────────────────────────────┐         │
│  │  ipcMain.handle                                     │         │
│  └────────────────────┬───────────────────────────────┘         │
│                       │ N-API (Function::New)                    │
├───────────────────────┼──────────────────────────────────────────┤
│  C++ 原生模块         │ tetris_core.node                        │
│  ┌────────────────────▼───────────────────────────────┐         │
│  │  TetrisGame 类 (native/tetris_core.cpp)             │         │
│  └────────────────────────────────────────────────────┘         │
└──────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────┐
│  HTTP API 服务器 (back_end/) — 独立 C++17 TCP Socket 服务器      │
│  ┌────────────────────────────────────────────────────┐         │
│  │  REST API :8920 → 同 C++ 引擎                       │         │
│  └────────────────────────────────────────────────────┘         │
└──────────────────────────────────────────────────────────────────┘
```

## 2. 进程间通信接口（IPC）

### 2.1 桥接机制

通过 `preload.js` 的 `contextBridge.exposeInMainWorld` 暴露 `window.nativeAPI` 对象，渲染进程通过 `ipcRenderer.invoke` 调用主进程处理器。

| 文件 | 职责 |
|------|------|
| `preload.js` | 定义 `window.nativeAPI` 接口，绑定 IPC 通道 |
| `main.js` | 注册 `ipcMain.handle` 处理器，调用 C++ addon |
| `addon.cpp` | N-API 绑定层，导出 C++ 函数给 JS |

### 2.2 游戏操作接口

#### `nativeAPI.init(gameType)`

创建并初始化游戏实例。

- **参数**：`gameType: {isAI: boolean}` — AI 实例或玩家实例
- **返回**：`void`
- **IPC 通道**：`game:init`
- **C++ 函数**：`createGame(isAI) → External<GameWrapper>`

#### `nativeAPI.move(params)`

移动当前方块。

- **参数**：`{game: 'player'|'ai', dx: int, dy: int}`
- **返回**：`boolean` — 移动是否成功
- **IPC 通道**：`game:move`
- **C++ 函数**：`move(wrapper, dx, dy) → bool`
- **错误处理**：原地碰撞返回 `false`，不改变游戏状态

#### `nativeAPI.rotate(params)`

顺时针旋转方块。

- **参数**：`{game: 'player'|'ai'}`
- **返回**：`boolean` — 旋转是否成功
- **IPC 通道**：`game:rotate`
- **C++ 函数**：`rotate(wrapper) → bool`
- **踢墙检查**：旋转后若碰撞，自动尝试左/右微移各一格

#### `nativeAPI.hardDrop(params)`

硬降 — 方块瞬间落到底部并锁定。

- **参数**：`{game: 'player'|'ai'}`
- **返回**：`boolean`
- **IPC 通道**：`game:hardDrop`
- **C++ 函数**：`hardDrop(wrapper) → bool`
- **副作用**：触发锁定 → 消行检测 → 新方块生成

#### `nativeAPI.getGhostY(params)`

获取 Ghost Piece 的 Y 坐标。

- **参数**：`{game: 'player'|'ai'}`
- **返回**：`int` — 底部投影 Y
- **IPC 通道**：`game:getGhostY`
- **C++ 函数**：`getGhostY(wrapper) → int`

#### `nativeAPI.update(params)`

推进一帧游戏逻辑（重力、锁定延迟、AI）。

- **参数**：`{game: 'player'|'ai', dt: double}` — dt 为帧时间差（ms）
- **返回**：`void`（状态更新在 C++ 内部）
- **IPC 通道**：`game:update`
- **C++ 函数**：`update(wrapper, dt) → void`
- **逻辑**：重力累加 → 到达间隔则下落 → 着陆启动锁定时 → 锁定超时则锁定 → 消行检测

#### `nativeAPI.aiTick(params)`

AI 模式专用 — 同步执行 AI 决策和游戏更新。

- **参数**：`{dt: double}`
- **返回**：`void`
- **IPC 通道**：`game:aiTick`
- **C++ 函数**：`aiStep(wrapper, dt) → void`
- **逻辑**：AI 思考（评估所有候选位置）→ 生成行动队列 → 按时间间隔执行

#### `nativeAPI.getState(params)`

获取游戏完整状态快照（最核心接口，每帧调用）。

- **参数**：`{game: 'player'|'ai'}`
- **返回**：完整游戏状态对象（见 2.3 节）
- **IPC 通道**：`game:getState`
- **C++ 函数**：`getState(wrapper) → Napi::Object`

#### `nativeAPI.setDifficulty(params)`

设置 AI 难度。

- **参数**：`{game: 'player'|'ai', difficulty: 'easy'|'medium'|'hard'}`
- **返回**：`void`
- **IPC 通道**：`game:setDifficulty`

#### `nativeAPI.setBuildMode(params)`

切换建造模式。

- **参数**：`{game: 'player'|'ai', buildMode: boolean}`
- **返回**：`void`
- **IPC 通道**：`game:setBuildMode`

#### `nativeAPI.available()`

检测 C++ 引擎是否可用。

- **参数**：无
- **返回**：`boolean`
- **IPC 通道**：`native:available`
- **用途**：启动时检查，若不可用则显示错误提示

#### `nativeAPI.getSystemTheme()`

获取操作系统配色方案。

- **参数**：无
- **返回**：`'dark'|'light'`
- **IPC 通道**：`native:getSystemTheme`

### 2.3 状态对象完整格式

`getState` 返回的 JavaScript 对象结构：

```typescript
interface GameState {
    // 棋盘
    grid: number[][];                    // 20×10 二维数组
    gridNames: string[];                 // 扁平数组，200 项

    // 计分
    score: number;
    lines: number;
    level: number;
    stage: number;

    // 游戏控制
    gameOver: boolean;
    paused: boolean;

    // 活动方块
    piece: string | null;                // 如 "T", "S", "I"
    pieceX: number;
    pieceY: number;
    currentRotation: number;             // 0-3
    currentShape: number[][];            // 当前形状矩阵
    nextPiece: string | null;

    // 消行
    clearing: boolean;
    clearRows: number[];
    clearTimer: number;

    // 物理
    dropInterval: number;
    buildMode: boolean;
}
```

### 2.4 数据持久化接口

通过 IPC 通道实现的简易 Key-Value 数据库操作：

#### `nativeAPI.dbGet(key)`

- **参数**：`key: string` — 如 `"tetris_Alice_achievements"`
- **返回**：`any|null` — JSON 解析后的值，不存在返回 null
- **IPC 通道**：`db:get`
- **实现**：`JSON.parse(fs.readFileSync(data/{key}.json, 'utf-8'))`

#### `nativeAPI.dbSet(key, value)`

- **参数**：`key: string, value: any`
- **返回**：`boolean`
- **IPC 通道**：`db:set`
- **实现**：`fs.writeFileSync(data/{key}.json, JSON.stringify(value))`

#### `nativeAPI.dbDelete(key)`

- **参数**：`key: string`
- **返回**：`boolean`
- **IPC 通道**：`db:delete`

#### `nativeAPI.dbDeletePrefix(prefix)`

删除所有匹配前缀的键。

- **参数**：`prefix: string`
- **返回**：`boolean`
- **IPC 通道**：`db:deletePrefix`
- **用途**：删除账户时清理所有关联数据

| 通道 | 方向 | 参数 | 返回 | 调用频次 |

| `game:rotate` | renderer→main | `{game}` | `boolean` | 中（按键） |
| `game:hardDrop` | renderer→main | `{game}` | `boolean` | 低（按键） |
| `game:getGhostY` | renderer→main | `{game}` | `int` | 中 |
| `game:update` | renderer→main | `{game,dt}` | `void` | **每帧** |
| `game:aiTick` | renderer→main | `{dt}` | `void` | **每帧**（AI 模式） |
| `game:getState` | renderer→main | `{game}` | `GameState` | **每帧** |
| `game:setDifficulty` | renderer→main | `{game,difficulty}` | `void` | 低 |

## 3. C++ N-API 接口

### 3.1 N-API 绑定概述

文件 `native/addon.cpp` 使用 `node-addon-api` (N-API v7) 将 C++ 类暴露给 JavaScript。

```cpp
// 主进程 main.js 中加载
const addon = require('./build/Release/tetris_core.node');
```

### 3.2 导出的 C++ 函数

| N-API 函数名 | 参数 | 返回 | 对应 IPC | 说明 |
|-------------|------|------|----------|------|
| `createGame` | `(isAI: bool)` | `External<GameWrapper>` | `game:init` | 创建游戏实例，封装为 JS 可持有对象 |
| `reset` | `(wrapper)` | `void` | — | 重置游戏状态 |
| `move` | `(wrapper, dx, dy)` | `bool` | `game:move` | 移动方块 |
| `rotate` | `(wrapper)` | `bool` | `game:rotate` | 旋转方块（带踢墙） |
| `getGhostY` | `(wrapper)` | `int` | `game:getGhostY` | 计算底部投影 |
| `hardDrop` | `(wrapper)` | `bool` | `game:hardDrop` | 硬降 |
| `update` | `(wrapper, dt)` | `void` | `game:update` | 帧更新（重力+锁定） |
| `aiStep` | `(wrapper, dt)` | `void` | `game:aiTick` | AI 决策+执行 |
| `getState` | `(wrapper)` | `Object` | `game:getState` | 获取全量状态 |
| `setDifficulty` | `(wrapper, str)` | `void` | `game:setDifficulty` | 设置难度 |
| `setBuildMode` | `(wrapper, bool)` | `void` | `game:setBuildMode` | 切换建造模式 |
| `setPiece` | `(wrapper, name)` | `void` | — | 建造模式手动设方块 |

### 3.3 GameWrapper 类

```cpp
class GameWrapper {
    TetrisGame game;                   // 实际游戏实例
    bool isAI;                         // 是否为 AI
    std::mt19937 rng;                  // AI 随机数引擎
};
```

### 3.4 N-API 调用示例

```javascript
// 创建游戏实例
const wrapper = addon.createGame(false);  // player 实例

// 移动
const moved = addon.move(wrapper, -1, 0);  // 左移

// 获取状态
const state = addon.getState(wrapper);
// state.gameOver, state.score, state.grid, state.piece ...
```

### 3.5 错误处理策略

- C++ 异常（如越界访问）通过 `Napi::Error::New().ThrowAsJavaScriptException()` 抛出
- JS 侧 `try-catch` 包裹所有 C++ 调用点，捕获异常后 `console.warn`
- 若 C++ 引擎崩溃，不导致 Electron 进程退出

## 4. HTTP RESTful API（独立服务器）

### 4.1 服务器信息

| 属性 | 值 |
|------|-----|
| 端口 | 8920 |
| 协议 | HTTP/1.1 |
| 传输 | TCP Socket |
| 数据格式 | JSON |
| 架构 | 纯 C++17（无外部库），每请求一线程 |
| 会话超时 | 30 分钟 |

### 4.3 统一错误响应

```
{ "status": "error", "error": "游戏ID不存在", "code": 404 }
```

| 状态码 | 含义 |
|--------|------|
| 200 | 成功 |
| 400 | 请求数据格式错误 |
| 404 | 游戏会话或用户不存在 |
| 500 | 服务器内部错误 |

### 4.4 服务器架构

```cpp
// Thread-per-connection + 后台清理线程

main() {
    create socket, bind, listen
    start cleanupThread (30s interval)

    while (true) {
        client = accept()
        std::thread(handleClient, client).detach()
    }
}

handleClient(socket) {
    read → parse HTTP → route → execute → serialize JSON → write response
}

cleanupThread() {
    while (true) {
        sleep(30s)
        manager.removeExpiredSessions(30min)
    }
}
```

## 6. 接口安全设计

### 6.1 渲染进程隔离

```javascript
// preload.js — 只暴露必要接口，无 Node.js 模块访问
contextBridge.exposeInMainWorld('nativeAPI', {
    move: (args) => ipcRenderer.invoke('game:move', args),
    rotate: (args) => ipcRenderer.invoke('game:rotate', args),
    getState: (args) => ipcRenderer.invoke('game:getState', args),
    // ... 只暴露白名单方法
});
```

### 6.2 输入验证

- 所有 IPC 参数在 `main.js` 中做类型校验（`typeof` 检查）
- 游戏操作调用在 C++ 侧有状态合法性检查
- 数据库操作限制键名格式（`^[a-zA-Z0-9_-]+$`）

### 6.3 异常处理

```javascript
// main.js — 所有 IPC 处理器包裹 try-catch
ipcMain.handle('game:update', async (event, args) => {
    try {
        const wrapper = games[args.game];
        addon.update(wrapper, args.dt);
    } catch (e) {
        console.error('[C++ engine error]', e);
        throw e;  // 错误传递到渲染进程
    }
});
```

## 7. 接口调用频率约束

| 接口 | 建议最大频率 | 备注 |
|------|------------|------|
| `game:update` | 60 次/秒 | 跟随帧率 |
| `game:getState` | 60 次/秒 | 跟随帧率 |
| `game:move` | 不限（受键盘） | CPU 微秒级 |
| `game:hardDrop` | 不限 | 玩家主动触发 |
| `db:get` | 10 次/秒 | 文件 I/O 略慢 |
| `db:set` | 事件触发 | 只在成就/分数变化时写入 |
