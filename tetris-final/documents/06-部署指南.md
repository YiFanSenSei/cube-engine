## 1. 开发环境搭建

### 1.1 前置条件

| 工具 | 版本要求 | 用途 |
|------|----------|------|
| Visual Studio 2022 | v17+ (MSVC v143) | C++ 编译 |
| CMake | 3.16+ | 构建系统 |
| Node.js | 18+ | Electron 运行 |
| vcpkg | 最新 | C++ 包管理 |
| Git | 任意 | 版本控制 |

### 1.2 安装步骤

**① 安装 Visual Studio 2022**

下载 [Visual Studio 2022](https://visualstudio.microsoft.com/)，工作负载选择：

- 「使用 C++ 的桌面开发」
- 包含 MSVC v143 生成工具
- 包含 Windows 10/11 SDK

**② 安装 vcpkg**

```powershell
git clone https://github.com/microsoft/vcpkg.git
cd vcpkg
.\bootstrap-vcpkg.bat

# 安装项目依赖
.\vcpkg install gtest --triplet x64-windows
```

**③ 安装 Node.js**

从 [nodejs.org](https://nodejs.org/) 下载 Node.js 18+。

### 1.3 验证环境

```powershell
# 验证编译器
cl --version

# 验证 CMake
cmake --version

# 验证 Node.js
node --version
npm --version

# 验证 vcpkg
vcpkg list
```

## 2. 后端 API 服务器部署

### 2.1 本地构建与运行

```powershell
# 1. 进入后端目录
cd back_end

# 2. 配置 CMake（使用 vcpkg 工具链）
cmake -B build -DCMAKE_TOOLCHAIN_FILE="<vcpkg-root>\scripts\buildsystems\vcpkg.cmake"

# 3. 构建
cmake --build build --config Release

# 4. 运行（默认监听 :8080）
.\build\Release\cube_server.exe
```

### 2.2 验证部署

```powershell
# 健康检查
curl http://localhost:8080/api/health

# 预期响应: {"status":"ok","activeGames":0,"uptime":"...","version":"1.0.0"}
```

### 2.3 Windows 服务部署（推荐）

使用 NSSM（Non-Sucking Service Manager）注册为 Windows 服务：

```powershell
# 下载 NSSM: https://nssm.cc/download

# 安装服务
nssm install TetrisAPI "C:\tetris\back_end\build\Release\cube_server.exe"

# 配置服务参数（自动重启等）
nssm set TetrisAPI AppDirectory "C:\tetris\back_end\build\Release"
nssm set TetrisAPI Start SERVICE_AUTO_START
nssm set TetrisAPI AppRestartDelay 5000

# 启动服务
nssm start TetrisAPI
```

### 2.4 Linux 部署

```bash
# 安装依赖
sudo apt-get update
sudo apt-get install -y cmake g++ libgtest-dev

# 构建
cd back_end
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build

# 运行
./build/cube_server &

# 注册为 systemd 服务
sudo cat > /etc/systemd/system/tetris-api.service << 'EOF'
[Unit]
Description=Tetris API Server
After=network.target

[Service]
Type=simple
ExecStart=/opt/tetris/back_end/build/cube_server
WorkingDirectory=/opt/tetris/back_end/build
Restart=always
RestartSec=5
User=tetris

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable tetris-api
sudo systemctl start tetris-api
```

## 3. Electron 客户端构建与部署

## 4. Docker 部署

### 4.1 后端 Docker 部署

```dockerfile
# Dockerfile.backend
FROM mcr.microsoft.com/windows/servercore:ltsc2022 AS build

WORKDIR /build
COPY back_end/ .

# 使用 MSVC 构建
RUN cmake -B build -DCMAKE_BUILD_TYPE=Release
RUN cmake --build build --config Release

# 运行阶段
FROM mcr.microsoft.com/windows/nanoserver:ltsc2022
WORKDIR /app
COPY --from=build /build/build/Release/cube_server.exe .
EXPOSE 8080
CMD ["cube_server.exe"]
```

### 4.2 Docker Compose

```yaml
# docker-compose.yml
version: '3.8'

services:
  tetris-api:
    build:
      context: .
      dockerfile: Dockerfile.backend
    ports:
      - "8080:8080"
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8080/api/health"]
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 10s
```

### 4.3 构建与启动

```powershell
docker compose build
docker compose up -d
```

## 5. 生产环境部署建议

### 5.1 架构推荐

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  Nginx       │     │  Nginx       │     │  Nginx       │
│  (反向代理)  │────▶│  (负载均衡)  │────▶│  (静态资源)  │
└─────────────┘     └─────────────┘     └─────────────┘
                           │
              ┌────────────┼────────────┐
              ▼            ▼            ▼
        ┌──────────┐ ┌──────────┐ ┌──────────┐
        │ API :8080│ │ API :8081│ │ API :8082│
        └──────────┘ └──────────┘ └──────────┘
```

### 5.2 Nginx 反向代理配置

```nginx
# /etc/nginx/sites-available/tetris
server {
    listen 80;
    server_name tetris.example.com;

    # API 反向代理
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # CORS 头
        add_header Access-Control-Allow-Origin *;
        add_header Access-Control-Allow-Methods "GET, POST, OPTIONS";
        add_header Access-Control-Allow-Headers "Content-Type, Authorization";

        # 超时设置
        proxy_connect_timeout 10s;
        proxy_read_timeout 30s;
    }

    # Swagger UI
    location /swagger/ {
        alias /opt/tetris/back_end/swagger/;
        index index.html;
    }
}
```

### 5.3 安全建议

| 项目 | 建议 |
|------|------|
| 防火墙 | 只开放 80/443 端口，8080 仅内网访问 |
| HTTPS | 使用 Let's Encrypt 免费证书 |
| CORS | 生产环境限制具体域名，不使用 `*` |
| API 鉴权 | 部署时启用 token 验证中间件 |
| 速率限制 | Nginx 层限制每 IP 每秒请求数 |
| 日志 | 配置日志轮转，避免磁盘占满 |

## 6. CI/CD 自动化部署

### 6.1 GitLab CI/CD 流水线

流水线配置见 `.gitlab-ci.yml`，包含 3 个阶段：

| 阶段 | 任务 | 说明 |
|------|------|------|
| **build** | build-electron | 编译 Electron + C++ 原生模块 |
| **build** | build-backend | 编译后端 API 服务器 |
| **test** | test-unittest | 运行 Google Test 单元测试 |
| **test** | test-jest | 运行 Jest 前端测试 |
| **test** | test-lint | ESLint 代码质量检查 |
| **deploy** | deploy | 手动触发部署到服务器 |

### 6.2 部署作业配置示例

```yaml
deploy-to-server:
  stage: deploy
  image: alpine:latest
  before_script:
    - apk add openssh-client
    - eval $(ssh-agent -s)
    - echo "$SSH_PRIVATE_KEY" | tr -d '\r' | ssh-add -
    - mkdir -p ~/.ssh
    - chmod 700 ~/.ssh
  script:
    - scp -r back_end/build/Release/cube_server.exe user@server:/opt/tetris/
    - ssh user@server "nssm restart TetrisAPI"
  only:
    - main
  when: manual
```

## 7. 运维与监控

### 7.1 健康检查

```powershell
# 基础健康检查
curl http://localhost:8080/api/health

# 持续监控（示例：每隔 10 秒检查一次）
while ($true) {
    $status = (Invoke-RestMethod http://localhost:8080/api/health).status
    Write-Host "$(Get-Date) - API Status: $status"
    Start-Sleep -Seconds 10
}
```

### 7.2 日志管理

服务器日志输出到控制台。生产环境建议：

```powershell
# 使用重定向记录日志
cube_server.exe > "C:\tetris\logs\api_$(Get-Date -Format 'yyyyMMdd').log" 2>&1

# 使用 Windows 事件日志（通过 NSSM 自动管理）
```

### 7.3 性能监控

推荐工具：
- **Windows**: PerfMon, Process Explorer, NSSM 内置日志
- **Linux**: Prometheus + Node Exporter, top/htop
- **API 级别**: JMeter 定期压测（见 `tests/jmeter/TetrisAPI_LoadTest.jmx`）

## 8. 常见问题

### Q: 后端启动报错 "bind failed: Address already in use"

```powershell
# 查找占用 8080 端口的进程
netstat -ano | findstr :8080

# 终止进程
taskkill /PID <进程ID> /F
```

### Q: CMake 找不到 GTest

确保使用 vcpkg 工具链文件配置：

```powershell
cmake -B build -DCMAKE_TOOLCHAIN_FILE="<vcpkg-root>\scripts\buildsystems\vcpkg.cmake"
```

### Q: node-gyp 编译失败

```powershell
# 确保安装了 Python
python --version

# 清理并重试
npx node-gyp clean
npx node-gyp rebuild
```

### Q: 客户端无法连接服务器

```powershell
# 1. 确认服务器正在运行
curl http://localhost:8080/api/health

# 2. 检查防火墙
netsh advfirewall firewall add rule name="Tetris API" dir=in action=allow protocol=TCP localport=8080
```
