### 1.3 失败分析

**① `ClearLineIncreasesScore`** — 手动填充棋盘行后调用 `clearLinesAndContinue()`，分数未增加。

- **可能原因：** `clearLinesAndContinue()` 在手动设置 grid（未通过正常 lockPiece 流程）时，score 更新依赖 `afterLock()` 中的逻辑，跳过该流程导致分数不变。
- **修复建议：** 测试改为通过 `hardDrop()` + `lockPiece()` 正常流程来构造消行场景，而非直接操作 grid。

**② `TetrisBonus`** — 同时消除 4 行后分数没有超过 100。

- **可能原因：** 同上，直接操作 grid 绕过了分数计算逻辑。此外 Tetris 奖励（4 行消除）的标准分数为 800 分，但当前实现分数计算可能在 `clearLinesAndContinue()` 而非 `afterLock()` 中。
- **修复建议：** 检查 `clearLinesAndContinue()` 中分数计算公式，确认其正确累加。

测试脚本：`tests/jmeter/TetrisAPI_LoadTest.jmx`

| 场景 | 用户数 | 持续 | 描述 |
|------|--------|------|------|
| **场景 1** 健康检查+认证 | 1 | 单次 | 验证服务器正常工作 |
| **场景 2** 游戏生命周期 | 5 | 单次 | 完整游戏流程（init→操作→状态→重置） |
| **场景 3** 并发压力 | 20 | 60s | 随机密集操作测试吞吐量 |
| **场景 4** 错误路径 | 1 | 单次 | 无效 gameId、空用户名、错误密码 |

### 5.2 运行方式

```bash
# 需要安装 JMeter 5.6.3+
jmeter -n -t tests/jmeter/TetrisAPI_LoadTest.jmx -l results.jtl -e -o results/
```

| 指标 | 说明 |
|------|------|

| 错误率 (% Error) | 失败请求占比 |

## 7. 问题清单与改进建议

### 7.1 现有问题

| 严重度 | 问题 | 模块 | 建议 |
|--------|------|------|------|
| 🟡 中 | 消行测试失败（2 例） | C++ 引擎 | 检查 `clearLinesAndContinue()` 的分数计算逻辑 |
| 🟢 低 | account.js 覆盖率低 | JS 前端 | 补充 account.js 测试（注册/登录/登出流程） |
| 🟢 低 | ESLint 配置兼容性 | 工具链 | 升级 ESLint 配置至 v10 或降级至 v8 |
| 🟢 低 | 缺少集成测试 | 全栈 | 添加 API 自动化集成测试（如 Supertest） |

### 7.2 改进建议

1. **增加 C++ 覆盖率**：补充边界条件测试（空棋盘、满棋盘、交替方块类型）
2. **API 集成测试自动化**：编写 Supertest 或 REST Client 脚本，CI 中自动运行
3. **性能基准**：在 CI 中添加 JMeter 无头运行，对比每次提交的性能变化
4. **端到端测试**：使用 Playwright 或 Puppeteer 测试 Electron 客户端
5. **测试报告自动化**：在 CI 中生成 HTML 测试报告并上传为 GitLab Pages
