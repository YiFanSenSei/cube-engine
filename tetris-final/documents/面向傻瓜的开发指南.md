## 📌 二、日常开发流程（按步骤来）

### 场景1：我想改游戏逻辑（比如改消行分数）

**这是你真正需要改的游戏本身的功能。**

**步骤：**

1. 打开 `native/tetris_core.cpp`
2. 找到你想改的地方（比如消行计分）
3. 改代码
4. **不需要动任何其他文件**，因为游戏引擎是"单体"的，所有逻辑都在一个文件里

**要编译测试的话：**
```powershell
# 先确保游戏能在 Electron 里跑
npm start
```

---

### 场景2：我想给游戏加一个新功能（比如加第8种方块）

**步骤：**

1. **改 C++ 引擎**：打开 `native/tetris_core.h`，在 `PIECE_NAMES` 和 `SHAPES` 里加上你的新方块
2. **同步到 API**：如果这个新功能需要 API 也支持，去 `back_end/api.cpp` 里加对应的处理
3. **改 OpenAPI 文档**：如果加了新的 API 接口，在 `back_end/cube-engine.openapi.yaml` 里写清楚
4. **写测试**：在 `tests/test_tetris_core.cpp` 里加对应的测试用例（看第6节）
5. **提交代码**：
   ```powershell
   git add .
   git commit -m "新增X型方块"
   git push
   ```

---

### 场景3：我想让前端通过 API 而不是 IPC 来玩游戏

**默认情况下，你的 Electron 游戏是通过 IPC（进程内通信）调用 C++ 引擎的。**

如果你想让**别的程序**（比如网页、手机App）也能玩你的游戏，就需要用 API。

**怎么用 API：**

1. **启动 API 服务器**：
   ```powershell
   cd back_end
   cmake -B build
   cmake --build build
   ./build/Debug/cube_server.exe
   ```

2. **服务器启动后**，你会看到：
   ```
   🎮 Tetris API Server v1.0
       监听端口: 8080
   ```

3. **用浏览器或 Postman 测试 API**：
   ```
   GET http://localhost:8080/api/health
   返回：{"code":0,"data":{"status":"ok","activeGames":0}}

   POST http://localhost:8080/api/game/init
   发送：{"isAI":false}
   返回：{"code":0,"data":{"gameId":"game_1","state":{...}}}
   ```

4. **所有可用的 API**（详细说明看 `back_end/cube-engine.openapi.yaml`）：

   | 请求方式 | 地址 | 发什么 | 拿回什么 |
   |---------|------|-------|---------|
   | GET | /api/health | 什么都不用发 | 服务器状态 |
   | POST | /api/game/init | {"isAI":false} | 新游戏的ID和初始状态 |
   | POST | /api/game/move | {"gameId":"game_1","dx":-1,"dy":0} | 移动结果和新状态 |
   | POST | /api/game/rotate | {"gameId":"game_1"} | 旋转结果和新状态 |
   | POST | /api/game/hardDrop | {"gameId":"game_1"} | 硬降结果和新状态 |
   | POST | /api/game/state | {"gameId":"game_1"} | 当前游戏状态 |
   | POST | /api/game/update | {"gameId":"game_1","dt":16} | 更新后的游戏状态 |
   | POST | /api/game/reset | {"gameId":"game_1"} | 重置后的状态 |
   | POST | /api/user/register | {"username":"test","password":"123"} | 注册结果 |
   | POST | /api/user/login | {"username":"test","password":"123"} | 登录结果和token |
   | POST | /api/user/highscore | {"id":1,"score":500} | 分数提交结果 |

### 场景4：我想运行单元测试

**单元测试 = 自动检查游戏有没有 bug**

**Windows 上（需要先安装 Google Test）：**

```powershell
cd tests
cmake -B build
cmake --build build
build\Debug\tetris_test.exe
```

如果看到类似这样的输出，说明测试通过了：
```
[==========] Running 25 tests from 5 test suites.
[----------] Global test environment tear-down
[==========] 25 tests passed. (0 ms total)
```

如果测试失败，会告诉你哪一行出错了，比如：
```
test_tetris_core.cpp:50: Failure
Expected: game.pieceX, which is 3, to be equal to originalX - 1, which is 2
```

那就说明 `move(-1,0)` 没有成功左移，你得去查 `tetris_core.cpp` 里的 `move` 函数。

**目前有哪些测试：**

| 测试类别 | 测试什么 |
|---------|---------|
| 初始状态 | 创建游戏后棋盘是否为空、分数是否为0 |
| 方块移动 | 左移、右移、不能移出边界 |
| 方块旋转 | 旋转后方块类型不变、4次旋转回到原位 |
| 消行计分 | 消一行加多少分、四消（Tetris）加更多分 |
| 硬降 | 硬降是否到底 |
| 幽灵方块 | 幽灵位置是否合法 |
| AI | AI 是否能找到合法落点 |
| 形状操作 | 每种形状是否正确、O形旋转不变 |

## 📌 三、Git 提交规范（怎么写提交信息）

**不要再写 "update"、"fix"、"改了" 了！**

正规的 Git 提交信息格式：

```
<类型>: <简短描述>

<详细说明（可选）>
```

**类型（选一个）：**

| 类型 | 什么时候用 | 例子 |
|-----|-----------|------|
| feat | 加新功能 | `feat: 新增X型方块` |
| fix | 修bug | `fix: 修复方块移出右边界的问题` |
| test | 加测试 | `test: 新增消行计分的测试用例` |
| docs | 改文档 | `docs: 更新开发指南` |
| refactor | 重构代码（不改功能） | `refactor: 优化碰撞检测逻辑` |
| style | 改格式/样式 | `style: 统一代码缩进` |
| chore | 改构建配置等杂事 | `chore: 更新.gitignore` |

**正确示例：**
```
feat: 新增双人合作模式

实现了两个玩家在同一棋盘上合作的游戏模式，
玩家1控制左侧，玩家2控制右侧。
```

**错误示例：**
```
fix bug
update
改了
```

## 📌 四、代码风格规则（写得像一个人写的）

### C++ 代码（`native/` 和 `back_end/`）

| 规则 | 正确 | 错误 |
|-----|------|------|
| 缩进用4个空格 | `    int x = 1;` | `\tint x = 1;` 或 `  int x = 1;` |
| 大括号另起一行 | `void func()`<br>`{`<br>`}` | `void func() {` |
| 变量名用驼峰 | `int pieceX;` | `int piece_x;` 或 `int PieceX;` |
| 函数名用驼峰 | `void hardDrop();` | `void hard_drop();` |
| 类名大写开头 | `class TetrisGame` | `class tetrisGame` |
| 常量用全大写 | `const int ROWS = 20;` | `const int rows = 20;` |

### JavaScript 代码（`renderer/js/`）

| 规则 | 正确 | 错误 |
|-----|------|------|
| 缩进用4个空格 | `    let x = 1;` | `  let x = 1;` |
| 变量名用驼峰 | `let gameMode;` | `let game_mode;` |
| 函数名用驼峰 | `function startGame()` | `function start_game()` |
| 字符串用单引号 | `let name = 'tetris';` | `let name = "tetris";` |
| 行尾加分号 | `let x = 1;` | `let x = 1` |

## 📌 五、Git 工作流程（多人协作）

### 第一次拉取代码

```powershell
# 克隆项目（只做一次）
git clone https://csgitlab.whu.edu.cn/你的仓库地址/tetris.git
cd tetris

# 安装依赖
npm install

# 编译 C++ 模块
npx node-gyp rebuild

# 启动游戏
npm start
```

### 日常开发流程

```
1. git pull              ← 先拉到最新代码
2. 写代码                 ← 改你的文件
3. git add .             ← 把改动的文件加进"待提交"列表
4. git commit -m "你的提交信息"  ← 提交到本地
5. git push              ← 推送到远程仓库
```

### 如果冲突了怎么办

**冲突** = 你和别人改了同一个文件的同一行。

```
1. git pull
   你会看到：CONFLICT (content): Merge conflict in xxx.cpp

2. 打开那个文件，你会看到：
   <<<<<<< HEAD
   你写的代码
   =======
   别人写的代码
   >>>>>>> branch-name

3. 改成你想要的样子（删掉 <<<<<<< ======= >>>>>>> 这些标记）

4. git add .
   git commit -m "解决冲突"
   git push
```

## 📌 六、怎么给 C++ 引擎加测试

**写测试一点也不难！就是"给它一个输入，看它输出对不对"**

### 教你写第一个测试

打开 `tests/test_tetris_core.cpp`，在最底下加：

```cpp
// 测试：分数不能为负数
TEST(TetrisCoreTest, ScoreCannotBeNegative) {
    TetrisGame game(false);
    // 刚创建的游戏分数应该是0
    EXPECT_GE(game.score, 0);  // ASSERT：score 大于等于 0
}
```

- `TEST(组名, 测试名)` — 声明一个测试
- `EXPECT_EQ(a, b)` — 检查 a 是否等于 b
- `EXPECT_NE(a, b)` — 检查 a 是否不等于 b
- `EXPECT_GT(a, b)` — 检查 a 是否大于 b
- `EXPECT_LT(a, b)` — 检查 a 是否小于 b
- `EXPECT_TRUE(x)` — 检查 x 是否为 true
- `EXPECT_FALSE(x)` — 检查 x 是否为 false

### 测试示例：测试左移

```cpp
TEST(TetrisCoreTest, MoveLeftWorks) {
    TetrisGame game(false);
    int oldX = game.pieceX;              // 记下原来的位置
    bool success = game.move(-1, 0);     // 向左移一格
    EXPECT_TRUE(success);                // 应该成功
    EXPECT_EQ(game.pieceX, oldX - 1);    // X坐标应该减1
}
```

**记住：每次改完 C++ 引擎的代码，都要跑一遍所有测试，确保没搞坏任何东西！**

## 📌 七、CI/CD 是什么（不用自己操作，但要知道）

**CI/CD = 自动帮你检查代码有没有问题的机器人**

以后你们配置好 GitLab CI 后：
1. 你 `git push` 提交代码
2. 机器人会自动：
   - 编译你的 C++ 代码（看能不能编译通过）
   - 运行所有单元测试（看有没有搞坏功能）
   - 运行代码质量检查（看代码写得规不规范）
3. 如果失败了，会发邮件告诉你
4. 去 GitLab 上看具体哪里失败了，修好再提交

**所以：提交代码前先自己在本地跑一遍测试，别等机器人发现错误才改！**

## 📌 八、常见问题

### Q：我改了 C++ 代码，需要重新编译什么？

**答：**
- 如果只是改 `native/tetris_core.cpp`：需要 `npx node-gyp rebuild` 重新编译 Electron 用的 C++ 模块
- 如果改了 `back_end/` 的代码：需要 `cmake --build build` 重新编译 API 服务器

### Q：我改了前端代码，需要编译吗？

**答：不需要！** 前端是 HTML/JS，改完保存，刷新游戏（按 F5 或重新打开）就能看到效果。

### Q：API 服务器和游戏可以同时运行吗？

**答：可以！** 互不干扰。游戏用 IPC 通信，API 服务器用 HTTP 通信，两者各自独立。

### Q：我完全搞砸了，怎么回到之前的状态？

**答：**
```powershell
# 放弃所有本地修改，回到最后一次提交的状态
git checkout -- .
# 或撤回最后一次提交（但保留改动）
git reset --soft HEAD~1
```

### Q：我不小心把不该提交的文件提交了怎么办？

**答：** 把那个文件名加进 `.gitignore`，然后：
```powershell
git rm --cached 那个文件的名字
git commit -m "chore: 移除不该提交的文件"
```
